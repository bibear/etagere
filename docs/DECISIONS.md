# Decisions

Short log of product and technical decisions. Newest last.

| # | Date | Decision | Why |
|---|---|---|---|
| D-01 | 2026-10-31 | AGPL-3.0 license | Self-hosted server: forks that host it for others must stay open. |
| D-02 | 2026-10-31 | One copy per ISBN, plus loans to people outside the household | Matches a household shelf; a loan locks the book like a reading does. |
| D-03 | 2026-10-31 | Home Wi-Fi only, no accounts; server refuses non-private IPs | Design principle "everything stays at home"; remote access would need auth and exposed HTTPS. |
| D-04 | 2026-10-31 | Everyone on the LAN can do everything | Household trust model, simplest onboarding. |
| D-05 | 2026-10-31 | App in French and English, repository in English | Reach open source contributors; household users get their language. |
| D-06 | 2026-10-31 | v1 adds to the design: manual entry, edit/delete book, profile management, dark mode, ideas to buy | Chosen by the maintainer. Not in v1: CSV import/export, multiple copies. |
| D-07 | 2026-10-31 | Recommendations: books on the shelf + ideas to buy from Open Library | Ideas to buy are the only other outbound call, cached 24 h. |
| D-08 | 2026-10-31 | Distribution: Docker image + `npx etagere-server`; Android APK on GitHub Releases; iOS via PWA; no store submission yet | No developer store accounts yet. Everything for later submission is prepared. |
| D-09 | 2026-10-31 | No hosted CI: `npm run check` + versioned pre-push hook | No GitHub Actions available. |
| D-10 | 2026-10-31 | Push straight to `main`, one commit per logical change, closing its issue | Personal project, fast feedback loop. |
| D-11 | 2026-10-31 | `node:sqlite` (built into Node 24) instead of a native SQLite module | No native compilation for `npx` and Docker. |
| D-12 | 2026-10-31 | Native apps talk plain HTTP to the LAN server: Android `usesCleartextTraffic`, iOS `NSAllowsLocalNetworking` + local network usage description | LAN-only server has no certificate. |
| D-13 | 2026-10-31 | PWA scanning: live camera only in a secure context (`localhost`); over plain-HTTP LAN the PWA falls back to "take a photo of the barcode" (`<input type=file capture>`) decoded with `@zxing/browser` | Browsers block `getUserMedia` on non-HTTPS origins. |
| D-14 | 2026-10-31 | Inputs validated by zod schemas in `@etagere/shared` (shared by server and app forms): unknown keys rejected, text trimmed, blank optional text stored as null, any `#RRGGBB` profile color accepted, ISBN normalised to ISBN-13 at the boundary | One source of truth for limits; strictness catches client bugs early. |
| D-15 | 2026-10-31 | i18n with a tiny in-house `translate()` in `@etagere/shared` (typed dot-path keys, `{{param}}` interpolation, `_one`/`_other` plurals) instead of i18next | Two languages, a few hundred strings: no dependency needed, keys checked by TypeScript and a parity test. |
| D-16 | 2026-10-31 | Generated cover color = FNV-1a hash of the normalised title (case, accents, spaces ignored) modulo the 10-color design palette; values pinned by a test | Same color on every device and across releases. |
| D-17 | 2026-10-31 | Migrations are numbered TypeScript modules exporting their SQL (`server/src/db/migrations/00N_name.ts`, listed in `migrations/index.ts`), each applied in its own transaction | Same SQL-file semantics, but bundled with the code: nothing to copy at build time for `npx` and Docker. |
| D-18 | 2026-10-31 | Accent and case insensitive search through an SQL function `fold(text)` registered on the connection | SQLite has no `unaccent`; keeps search in SQL. |
| D-19 | 2026-10-31 | Server structure: `buildApp(deps)` factory with injected `db`, `fetch`, `now`, `dataDir`, `lanUrls`, logger; deps reachable in routes as `app.deps`; one Fastify plugin per route group in `server/src/routes/`, mounted under `/api`; route inputs parsed with `parseInput(zodSchema, …)`, expected errors thrown as `HttpError` | Testable through `fastify.inject` with fakes; parallel work touches separate files. |
| D-20 | 2026-10-31 | `400 invalid_input` carries `fields` (the invalid input paths); unknown `/api` routes answer `404 { code: "not_found" }`; request logs hold method, URL and status only | Forms can highlight fields; logs carry no device address or content. |
| D-21 | 2026-10-31 | Household name from `ETAGERE_HOUSEHOLD_NAME` (default "Étagère") until the settings ticket stores it | Health needs a value from day one. |
| D-22 | 2026-10-31 | Jest runs with `--experimental-vm-modules` (`node … jest.js`, cross-platform) | Fastify's `inject` loads an ESM-only dependency (`cookie`). |
| D-23 | 2026-10-31 | App structure: routes in `app/app/` (expo-router, tabs in `(tabs)/`), components in `app/src/components/`, one `AppProviders` (safe area, theme, i18n, session, TanStack Query); the session (profile + server address) is stored as one JSON entry in AsyncStorage (`etagere.session`) and exposes an `ApiClient` bound to both (`useApi()`) | One obvious place per concern for parallel work; tests render through `renderWithProviders` + `fakeFetch`. |
| D-24 | 2026-10-31 | Default server address: PWA → its own origin; web in development → same host, port 4848; native → `http://etagere.local:4848` | Matches the discovery order of the architecture without any configuration in development. |
| D-25 | 2026-10-31 | App identifiers `org.etagere.app` (iOS bundle id, Android package), URL scheme `etagere` | Neutral, project-owned names; can change before the first store submission. |
| D-26 | 2026-10-31 | Dev dependencies added: `eslint-plugin-react-hooks` (lint), `pino` (server log capture in tests, already Fastify's logger), `tsx` (dev server); app: `expo-crypto` (UUID v4 for the profile id), `@expo-google-fonts/*`, `react-native-svg`, `@tanstack/react-query`, AsyncStorage | Well-known, maintained; versions aligned with Expo SDK 58. |
| D-27 | 2026-10-31 | Profiles: a device only writes its own profile (`403 profile_mismatch` otherwise); removing a member puts down their current reading; re-writing a removed profile restores it | Keeps the trust model simple while preventing a stale device from locking books forever. |
| D-28 | 2026-10-31 | Realtime events go through an in-process `EventBus` decorated as `app.events`; routes publish after the mutation is committed | One place for the WebSocket route to subscribe; routes stay testable without sockets. |
| D-29 | 2026-10-31 | App stack routes `/onboarding`, `/server`, `/book/[id]`, `/profile`; the tabs layout redirects to `/onboarding` while the device has no profile; query keys grouped by prefix in `app/src/api/queryKeys.ts` | One gate, one place for keys that realtime events and mutations invalidate. |
| D-30 | 2026-10-31 | Server settings save an address only after its `/api/health` answers, and switching server clears every cached query | A typo must not strand the app; data from one household must not show on another. |
| D-31 | 2026-10-31 | Books list: search in SQL (`fold` + `instr`, no LIKE wildcards to escape), filter / sort / counts in memory over the matching books; French collation for title and author sorts; `source` derived from the presence of an ISBN | A household shelf is a few thousand books at most; keeps `BookInput` unchanged. |
| D-32 | 2026-10-31 | Library: the design's "See all" link becomes a "Sort" toggle (recently added → title → author), the grid lists every result, every filter chip shows its count, search is debounced 250 ms | The grid already shows everything; sort is in the contract and needed a control. |
| D-33 | 2026-10-31 | Book detail: "Put it down" under "I finished this book" for the current reader; deleting a review asks an inline confirmation (no native alert, works on the web); comment dates relative for 7 days, then day + month | Covers the whole reading-lock contract from the book; same behaviour on every platform. |
| D-34 | 2026-10-31 | Cover download is best effort: only `https://covers.openlibrary.org/` sources, image type checked from the bytes, 5 MB cap, written atomically as `<bookId>.jpg`; a failure never fails the book creation | The app always has a generated cover to fall back on; no untrusted file is ever served. |
| D-35 | 2026-10-31 | Reading lock: one current reading per member (starting a book puts the previous one down, as the design shows "1 en cours"); finish / put down by someone else than the current reader → `409 not_reader`; the partial unique index is the final arbiter of concurrent starts | Matches the readings screen; the lock stays correct even if two requests race past the check. |
| D-36 | 2026-10-31 | Book form routes `/book/new` (`?isbn=` prefills) and `/book/edit/<id>`; authors and genres typed as comma-separated lists; delete confirmed inline in the screen (not `Alert`, a no-op on web); after a book mutation the app invalidates every cached query | One form for manual entry, lookup prefill and edit; works the same on native and PWA; realtime events refresh other devices. |
| D-37 | 2026-10-31 | Realtime: `@fastify/websocket` 11.3.4 (registered at the root, gives `injectWS` for tests) + `@types/ws` (dev); events carry the book id (books, comments) or the profile id; the app invalidates key prefixes per event type and refreshes everything after a reconnection | Official Fastify plugin; prefix invalidation stays correct as screens add queries under the shared keys. |
| D-38 | 2026-10-31 | Scanner: platform code behind a `ScannerBackend` (camera view + permission hook; `src/scan/backend.tsx` native with expo-camera, `backend.web.tsx` for the PWA); one tap on "Add to library" adds the book (the design's "added as soon as it is read" line becomes "Then one tap adds it"); after adding, the scanner stays open on "Scan another" for a shelf session; a repeated code is ignored for 3 s | Testable without a camera; a misread never adds a wrong book silently; fast batch scanning. |
| D-39 | 2026-10-31 | Web scanner: one `BarcodeDecoder` interface (`BarcodeDetector` with EAN-13, else ZXing loaded on demand with `@zxing/browser` + `@zxing/library`); live mode decodes a video frame every 250 ms; the photo button stays available when the live camera is refused or missing; no torch on the web | `BarcodeDetector` is missing on iOS Safari and Firefox; ZXing stays out of the initial bundle; the photo path works on every browser, over plain HTTP too. |
| D-40 | 2026-10-31 | Loans: a book being read cannot be lent, even by its reader (put it down first); any member records the return; returning a book that is not lent answers `409 not_lent`; the partial unique index arbitrates concurrent loans | Same lock semantics as readings; the household trust model lets whoever gets the book back say so. |
| D-41 | 2026-10-31 | Recommendations: zero-score books stay in `onShelf` (max 20) after the scored ones; the featured pick is the best available book and leaves `onShelf`; `Reason` gains an optional `because` (titles I finished) so the app can say "Because you read Dune" like the design; household points and quotes only count other members' comments; ideas to buy cache each Open Library search URL for 24 h in memory (failures not cached, owned books filtered on every request, `upstream_unavailable` only when every search fails) | Matches the design copy; a new member is never shown an empty screen; one flaky search does not hide the others. |
| D-42 | 2026-10-31 | Discovery: `bonjour-service` 1.4.4 announces `_etagere._tcp` / `etagere.local` (best effort, `ETAGERE_MDNS=0` to disable); `qrcode` 1.5.4 draws the start-up QR code of the first LAN IPv4 URL (plain `http://…` so a phone camera opens the PWA and the app can pair); the app's QR scan accepts any `http(s)` URL and saves it only after `/api/health` answers; at first launch a dead saved address falls back to `etagere.local` and is forgotten | Many Android phones do not resolve `.local`: the IP URL in the QR code is the reliable path, mDNS the convenient one. |
| D-43 | 2026-10-31 | App readings, loans and recommendations: the finished list sorts on the device (most recent → title → author); lending is an inline form on the book detail (borrower's first name), "It's back" returns it; recommendation reasons are sentences the app builds from `kind` / `ref` (and the `because` titles when present); ideas to buy show generated covers and, when they have an ISBN, open the add form prefilled ("Bought it: add") | Same behaviour on native and web without modals; the phone never calls Open Library itself; a bought idea becomes a book in one step. |
| D-44 | 2026-10-31 | npm package: the server is bundled with `esbuild` 0.28.2 (dev dependency, already used by `tsx`) into one CommonJS `dist/index.js`; `@etagere/shared` is bundled (dev dependency) and every other runtime import must be a declared dependency (checked by a test); `HOST` bound to loopback hides the LAN addresses and the mDNS announce | Users install a plain JavaScript package (no TypeScript runtime, no workspace package on npm); a missing dependency fails the gate instead of a user's `npx`. |
| D-45 | 2026-10-31 | PWA: served with `@fastify/static` 10.1.6 (official Fastify plugin, pinned); SPA fallback through the root not-found handler (GET/HEAD, outside `/api`, no file extension); the export is completed by our own build step (manifest, service worker with a content-hashed precache list, icons drawn in code so no binary lives in the repo) rather than a PWA plugin; the service worker precaches only the shell (fonts are megabytes: cached on first use) and registers only in a secure context | Path traversal, ranges and MIME types handled by a maintained plugin; Expo's metro web export has no manifest or service worker of its own; browsers refuse service workers over plain HTTP anyway. |
| D-46 | 2026-10-31 | Docker: the image installs the packed npm package (one build path for both channels), runs as the unprivileged `node` user, compose uses a named volume (a bind mount needs `chown 1000:1000`), multi-arch amd64 + arm64 via `docker buildx`; Docker is not installed on the development machine, so the image is pinned by file-level tests and first built by the maintainer at release | Raspberry Pi and NAS are typical hosts; a named volume avoids the root-owned bind-mount trap. |
| D-47 | 2026-10-31 | Profile settings (`/profile`): rename and recolor my profile (saved on the server, then on the device, then every query refreshed since names show everywhere); remove another member after an inline confirmation (a member does not remove themself there); the household name is shown read-only from `/api/health`; language and theme are shown as following the phone (no in-app override) | No contract endpoint stores the household name yet; keeps one source of truth for language and theme. |
| D-48 | 2026-10-31 | Mobile builds: `expo-build-properties` ~58.0.12 sets Android cleartext (the `android.usesCleartextTraffic` key of app.json is not an Expo config field); native icons and splash are rendered by the PWA icon code (`iconPng(size, scale)`, adaptive foreground at 72 % for circular masks), committed as PNG and checked by a test; EAS uses the remote app version source with `autoIncrement` for production | Official Expo plugin; one icon source for PWA and native, no image tool or design export needed. |
| D-49 | 2026-10-31 | Releases: one version for every workspace and the app (`npm run release:version -- X.Y.Z`), tag `vX.Y.Z`; the documentation is tested (npm scripts and EAS profiles it mentions exist, relative links resolve, store texts fit the App Store / Google Play limits); store privacy answers: no data collected; the privacy policy is a Markdown page of the repository | The maintainer releases by hand from his machine: commands that drift from the build files would fail at the worst moment. |
| D-50 | 2026-10-31 | Offline copy built on TanStack's own `dehydrate` / `hydrate` (no persister package): one storage entry tagged with server + profile, 30-day expiry, search results not saved, `gcTime` 24 h; offline = last query or mutation failed with a network error (not the OS network state), health probed every 10 s; write buttons opt in with `needsServer` | No new dependency or lock churn for ~100 lines; a LAN server can be down while the phone has Wi-Fi, so the API itself is the signal. |
| D-51 | 2026-10-31 | Saving another server address in the server settings first writes the device profile there (`PUT /api/profiles/:id` with the same id, name and color, which creates it or restores a removed one); the address is saved only when that succeeds | Without it, every write on the new server answered `401 unknown_profile` and the only way out was the profile screen. Switching server is an explicit act of the member, so re-joining is what they mean. |
| D-52 | 2026-10-31 | LAN guard also checks the `Host` header: a private IP literal, `localhost`, a `*.local` name or a name of `ETAGERE_ALLOWED_HOSTS` (comma separated); anything else, or no Host, answers `403 outside_lan`; the same names are the allowed CORS / WebSocket origins | The source address alone does not stop DNS rebinding from a public website opened on a household device; a home DNS name stays possible through the setting. |
| D-53 | 2026-10-31 | `ETAGERE_PUBLIC_URL` replaces the detected LAN addresses in the start-up banner, the QR code and `/api/server-info` (its host name joins the allowed hosts); without it, container / VM bridge interfaces are skipped and VPN tunnels ranked last; an invalid value stops the server at start | A container in bridge mode (and Docker Desktop, which has no host networking) only sees its own 172.x address; a wrong QR code is worse than a start-up error. |
| D-54 | 2026-10-31 | Book edit sends only the fields the member changed (compared as typed text with the form built from the book); an untouched authors / genres field keeps the book's own list; nothing changed: no request, back to the book | Open Library subjects and "Last, First" authors contain commas: re-splitting the whole form on every save silently multiplied genres and authors. |
| D-55 | 2026-10-31 | Profile initials (avatars, library header) use white or the dark ink `#16201B`, whichever has the higher WCAG contrast on the profile color (`textColorOn` in `@etagere/shared`); ochre therefore gets dark ink, unlike the mockup | White on ochre is about 3:1 (fails AA) and any `#RRGGBB` is accepted, so a pale custom color made the initials invisible. |
